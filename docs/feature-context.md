## Standing Constraints

<!-- Cross-cutting facts every future plan must respect. Promote here when an
     entry's lesson outlives its feature. Prune when no longer true. -->

- **Runtime scripts: edit `runtime-src/`, never `public/runtime/*.js`.** The three
  `public/runtime/*.js` are GENERATED by esbuild (`npm run build:runtime`) from TS modules
  in `runtime-src/` (shared code in `runtime-src/common/`). Each bundles to a single
  self-contained **classic IIFE** — still cross-origin-loadable, re-injectable, self-gating;
  no `type="module"`, no runtime imports. The `.js` are committed and CI drift-checks them
  (`git diff --exit-code -- public/runtime`); the `.js.map` are external + gitignored.
  `.prettierignore` excludes the generated `.js` so the pre-commit `pretty-quick` doesn't
  fight the drift-check. **Do NOT add a schema/validation library to the runtime bundle** —
  it inlines into the injected script (zod added ~50KB); strict validation belongs
  server-side. Validate with `npm run typecheck:runtime` + `npm test` (vitest + happy-dom).
- **Runtime config is untrusted input.** The `[data-vp-config]` JSON is authored by
  course creators (and later a content endpoint). Every config-derived value written to
  `innerHTML` must go through `esc()`; ids used in selectors must go through `CSS.escape`.
- **`window.__vpTrustedOrigins`** is the single opt-in list for cross-origin trust
  (postMessage peers + language-pack asset origins). Default is same-origin only.

## 2026-07-24 · (no ticket) · Runtime augment security hardening

- **Decision**: Fixed XSS by escaping at the `innerHTML` interpolation sites (`esc()` +
  `CSS.escape`) rather than rewriting to DOM construction — surgical, behaviour-preserving,
  and leaves the larger imperative-rendering refactor for a separate pass.
- **Decision**: One `vpTrustedOrigins` set backs both the postMessage origin check and the
  language-pack asset allowlist; outbound player events now target a concrete per-iframe
  origin, never `'*'`.
- **Deviation**: No test framework was added (repo has none, and the IIFEs are not
  importable). Verified via a browser harness loading the real script; standing up
  Vitest+jsdom is deferred as a project-level decision.
- **Gotcha**: `npm run build` fails locally on missing `DATABASE_URL`/`BLOB_READ_WRITE_TOKEN`
  env vars — unrelated to runtime scripts (static `public/` assets, outside the compile graph).
- **Open**: hosting mode (public static vs Vercel bypass-secret) and whether cross-origin
  sidebar iframes exist remain host/operational decisions; code uses safe defaults.
- **Superseded**: the "no test framework / verify via browser harness" note below is
  obsolete as of the TS migration — vitest + happy-dom now exist (`npm test`).

## 2026-07-24 · (no ticket) · Runtime TS module migration (build → classic IIFE)

- **Decision**: Source moved to `runtime-src/` (TS), bundled by esbuild to classic IIFEs in
  `public/runtime/`; distribution model unchanged. Unlocks shared `common/`, types, tests.
- **Decision**: Generated `.js` committed + CI drift-check; source maps external + gitignored;
  target es2019; output unminified for third-party-page debuggability.
- **Deviation**: Dropped zod from the runtime (it inlined ~50KB into the injected bundle);
  `parseVpConfig` stays lenient, strict validation deferred to the server-side content service.
- **Deviation**: Kept each entry's coupled renderer/attach logic as nested functions in
  `index.ts` (extracted only `styles`/`language-pack`/`data`/`prompt`) — behaviour-parity over
  maximal file-splitting.
- **Gotcha**: esbuild IIFEs are ES modules → no top-level `return`; each entry wraps logic in
  `main()` and assigns the status string to `window.__vp*Status`.
- **Next**: Preact/JSX for the `demo-overlays` UI is the intended follow-up (structurally
  removes the innerHTML XSS class).
