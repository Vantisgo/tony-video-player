# Resilience — safety net (never break the native player)

**Date:** 2026-07-24
**Source analysis:** `docs/reskin-player-resilience-analysis.md` (items F1, F2, F3, F4)
**Scope:** `runtime-src/reskin-player/{index,styles}.ts`, `runtime-src/demo-overlays/index.ts`
**Goal:** Guarantee the invariant: _if we cannot fully and correctly augment the player, leave the native player exactly as we found it and fully functional._ Behaviour-preserving for successful attaches.

**Stack constraints (read first):**

- Edit TypeScript under `runtime-src/`; **never** hand-edit `public/runtime/*.js` (generated by `scripts/build-runtime.mjs`, header says so).
- Each entry bundles to a standalone classic IIFE — shared code lives in `runtime-src/common/`.
- Standards (`.claude/CLAUDE.md`): no `any`, no unjustified assertions, immutable data, small pure functions, tests per acceptance criterion (Vitest + jsdom, `runtime-src/tests/`).
- Verify: `npm run typecheck:runtime`, `npm test`, `npm run lint`, `npm run build:runtime`.

**Priority order within this plan:** F1 → F2 → F3 → F4 (F1/F2 are the P0 core; F3/F4 are P2 refinements that build on F2's rollback path).

---

## F1 — Scope native-control-hiding CSS under a success marker (P0)

### Risk

`RESKIN_CSS` (`reskin-player/styles.ts:3-36`) is injected in `main()`
**unconditionally and before any attach succeeds** (`index.ts:43-48`). Rules
4-9 hide the native Vidstack/Mux chrome (`hls-video media-*`, `[slot]`) with
`display:none !important`. The custom controls are only built inside `attach()`,
which can bail or throw. Failure state: **native controls hidden + no reskin
controls = a player the user cannot pause, seek, or configure.** This turns an
acceptable degradation ("reskin didn't apply") into a broken player.

### Change

Re-scope rules 4-9 to require the success marker as an ancestor. The marker
`data-vp-reskinned="true"` is set on the host only after attach reaches the
mount step (`index.ts:159`) and removed on teardown (`index.ts:1025`), so
control-hiding becomes strictly tied to a live reskin. Rule 10 is already scoped
this way — mirror it.

```
/* before */
hls-video media-controls, hls-video media-poster, … { display:none !important; }
/* after */
[data-vp-reskinned="true"] hls-video media-controls,
[data-vp-reskinned="true"] hls-video media-poster, … { display:none !important; }
```

Apply the `[data-vp-reskinned="true"] ` prefix to `styles.ts:4`, `:5`, and the
block `:6-9`. `hls-video` is a descendant of the marked host
(`host = hls-video.parentElement`, `index.ts:157`), so the descendant combinator
resolves correctly. The `.vp-shell`/overlay/menu rules (`:11-35`) are unaffected
— they only match our own injected nodes.

### Acceptance criteria

- AC1: With `RESKIN_CSS` injected but **no** successful attach (no
  `[data-vp-config]`, or attach bailed), the native `media-*` controls remain
  visible and operable.
- AC2: After a successful attach, native chrome is hidden exactly as today
  (visual parity).
- AC3: After teardown (marker removed at `index.ts:1025`), native chrome
  returns.

## F2 — try/catch + auto-rollback around augmentation (P0)

### Risk

`attach()` sets `hlsEl.__vpAttached = true` (`index.ts:152`) and appends the
shell (`:185`) before wiring handlers and before its cleanup is registered
(`pushCleanup`, `:993`). A throw in between (e.g. a `q()` lookup returns `null`
because a future host change broke the shell template, then `.onclick` throws)
leaves an orphaned `.vp-shell`, a dangling `__vpAttached`, and — combined with
F1 — the `data-vp-reskinned` marker set (native chrome hidden) with no working
controls. `demo-overlays` `applySetup()` (`index.ts:87`) has the same exposure:
it mounts slots + sidebar and mutates host layout before any guard.

### Change

1. **reskin `attach()`** — wrap the body in `try/catch`. Build rollback
   incrementally so an early throw still cleans up: register a local
   `undo: (() => void)[]` and push a reversal as each host mutation happens
   (marker set → push marker clear; shell appended → push `shell.remove()`;
   `__vpAttached=true` → push `delete hlsEl.__vpAttached`). On catch, run `undo`
   in reverse, then report via the ops-telemetry hook (see ops plan F6). The
   final `pushCleanup` block (`:993`) still owns the success-path teardown; the
   `undo` list only covers the window before it is registered.
2. **demo `applySetup()`** — wrap in `try/catch`; on catch call
   `resetCleanup(CLEANUP_KEY)` (tears down registered listeners/observers) and
   remove the created nodes by id (`vp-slot-*`, `vp-demo-sidebar` — the same ids
   already removed defensively at `index.ts:117-123`), restoring the host DOM.

Keep catches narrow to augmentation code; do **not** swallow errors silently —
log (`console.error`) and beacon (ops plan). This satisfies the project's
no-silent-failure standard.

### Acceptance criteria

- AC1: Injecting a throw partway through `attach()` (after marker set / shell
  appended) leaves: no `.vp-shell` in the DOM, `__vpAttached` cleared, marker
  removed, native player fully functional.
- AC2: Injecting a throw in `applySetup()` leaves no `vp-slot-*`/`vp-demo-sidebar`
  nodes and no leaked observers/listeners (host DOM restored).
- AC3: A clean attach/setup is byte-for-byte unchanged in behaviour (the
  try/catch is transparent on the happy path).

## F3 — Preconditions before host mutation (P2)

### Risk

`tryFlexSibling()` (`demo-overlays/index.ts:718-758`) is the most invasive host
mutation: it sets sibling `display:none`, forces the parent to `flex`, and
reparents into `main`'s flex row before checking whether the result is usable
(it does revert on failure). `attach()` mounts the shell before confirming the
shell's own required nodes exist.

### Change

- **reskin:** after building the shell, assert the required control nodes
  resolved (`playPauseBtn`, `seekInput`, `timeLabel`, `overlayLayer` non-null).
  If any is null (future template/host breakage), bail via the F2 rollback
  **before** wiring handlers or hiding native chrome.
- **demo:** gate `tryFlexSibling()` on cheap preconditions before mutating —
  `main` and its parent exist, parent has ≥2 children, `main` has a non-zero box.
  If unmet, skip straight to `applyFixedRightRail()` (the less invasive path)
  rather than mutate-then-revert.

Preconditions must not cause false negatives during async React render — check
only structural facts that are stable once the config+video gate has fired
(`demo-overlays/index.ts:65-83` already guarantees both exist).

### Acceptance criteria

- AC1: When a required reskin control node is missing, no native chrome is
  hidden and no partial shell remains (F2 rollback runs).
- AC2: When flex-sibling preconditions are unmet, the host's sibling `display`
  and parent layout are never mutated; `applyFixedRightRail()` is used instead.
- AC3: On a normal LearningSuite layout, the sidebar still mounts as a flex
  sibling exactly as today.

## F4 — Post-attach self-verification with auto-rollback (P2)

### Risk

An attach can succeed without throwing yet be visually broken (overlay layer
collapsed to a zero box because a host change removed the positioning context).
A try/catch (F2) won't catch this — nothing throws.

### Change

After mount, defer one animation frame (layout may be async) and verify the
overlay layer has a non-zero box and overlaps the media element's rect
(`getBoundingClientRect`). If verification fails, run the F2 rollback so native
controls return. Guard against false positives: only verify once the media
element itself reports a non-zero box (skip while the player is off-screen /
display:none, re-checking on the next `scan()` tick rather than tearing down).

### Acceptance criteria

- AC1: If the shell mounts but the overlay layer has a zero box while the video
  has a non-zero box, the runtime auto-tears-down and the native player remains.
- AC2: A player that is temporarily off-screen (both boxes zero) is **not** torn
  down — it attaches once laid out.
- AC3: A correctly mounted overlay layer passes verification with no teardown and
  no behaviour change.

## Testing strategy

Vitest + jsdom, mirroring `runtime-src/tests/reskin-player/index.test.ts`
(which already stubs an `hls-video` + `[data-vp-config]` host). jsdom does not do
layout, so:

- **F1** — assert on the generated CSS text: every native-chrome rule is
  prefixed with `[data-vp-reskinned="true"]` and matches only under the marker
  (parse `RESKIN_CSS`; assert selectors). Add a DOM test toggling the marker.
- **F2/F3** — inject a fault (e.g. stub a shell node lookup to return `null`, or
  make a handler throw) and assert post-conditions: no `.vp-shell`, marker
  cleared, `__vpAttached` deleted, native element untouched.
- **F4** — stub `getBoundingClientRect` on the overlay layer / media element
  (jsdom returns zeros by default, so this path is directly testable) and assert
  teardown vs. defer.

One test per acceptance criterion (project rule).

## Open questions

1. **F4 thresholds** — exact "non-zero box" tolerance and how many `scan()`
   retries before giving up vs. reporting a failure. Proposed: any box with
   width·height > 0; report only after the F5/ops deadline (ops plan).
2. **F2 partial-rollback vs. eager cleanup registration** — alternative to the
   `undo` list is to register `pushCleanup` reversals incrementally as we mutate.
   Pick one style; the `undo` list is proposed for locality.

## Dependencies / cross-plan

- F2 and F4 emit failure signals consumed by **ops-telemetry plan** (F6/Part 5
  webhook). Ship the rollback here; wire the beacon there.

## Out of scope

- Generalizing the `hls-video` selector (adaptability plan, H1) — F1 keeps the
  tag-scoped CSS; H1 later addresses non-`hls-video` players.
- Any change to successful-attach rendering or the control layout.
